# ERPEZ Operational Entity Classification Matrix

> Authoritative classification of all 184 entities in `apps/backend/Dashboard/Dashboard.Domain/Entities` into **Tenant-Scoped** versus **Global Reference / System Standards**.

## 1. Classification Methodology & Invariants

Each operational entity is classified strictly according to its **ownership semantics**:

1. **`TenantScopedEntity : BaseEntity`**:
   - The entity is owned, authored, managed, or mutated by an individual tenant organization.
   - Requires `public Guid TenantId { get; set; }`.
   - Automatically isolated by the EF Core runtime Global Query Filter (`e => e.TenantId == CurrentTenantId`).
   - Tenant ownership is stamped at write-time (`Added`), immutable on `Modified`, and validated on `Deleted`.
   - Any natural or uniqueness keys must be compound with `TenantId` (e.g., `(TenantId, Code)`).

2. **`BaseEntity` (Global Reference / National Catalogs / System Standards)**:
   - The entity represents national public data, official government standards, or system-wide static lookup tables shared across all tenants.
   - Inherits directly from `BaseEntity` without `TenantId`.
   - No Global Query Filter is applied; accessible in read-only mode by all SaaS and On-Premise tenants.
   - Mutations are strictly restricted to system-level synchronization jobs (e.g., PS-DBM Hangfire sync) or platform administrative tools.

## 4. Key Takeaways & Architecture Decision Records (ADRs)

1. **National Catalogs Are Never Duplicated**: PS-DBM stock catalogs, UNSPSC item codes, and COA/DBM UACS Chart of Accounts are global singletons (`BaseEntity`). Syncing them updates the single shared operational database once, instantly benefiting all SaaS tenants without data replication.
2. **Organizational Data Is Strictly Tenant-Scoped**: While an agency follows Civil Service guidelines, its actual `Office` hierarchy, `FundSource` allotments (GAA/SARO numbers), `Plantilla` allocations, and `PurchaseRequest` transactions belong exclusively to the tenant (`TenantScopedEntity`).
3. **Compound Key Requirement**: For all 148 `TenantScopedEntity` classes, existing unique database constraints (such as `PRNumber`, `PONumber`, `Office.Code`, `Supplier.TIN`) will be updated during Phase 5 to include `TenantId` to allow different tenants to utilize the same internal identifiers safely.
